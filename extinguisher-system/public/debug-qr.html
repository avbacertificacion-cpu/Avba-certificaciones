🔍 Análisis Completo del Sistema de QR

📊 Flujo de Escaneo de QR

1. QR genera URL
https://gestion.avba.com.mx/extintores/public/validar-extintor.html?qr=43526180127

✓ CORRECTO: El QR se genera con la URL completa

2. Servidor recibe solicitud
GET /extintores/public/validar-extintor.html?qr=43526180127

? DESCONOCIDO: ¿Qué hace el servidor aquí?

3. .htaccess evalúa reglas
REQUEST_FILENAME = /home/...extinguisher-system/public/validar-extintor.html REQUEST_URI = /extintores/public/validar-extintor.html QUERY_STRING = qr=43526180127 Regla 1: ¿Es archivo real (-f)? → Si YES: NO REESCRIBIR (-L) → Si NO: Continuar Regla 3: ¿Coincide ^public/validar-extintor\.html$? → Si YES: NO REESCRIBIR (-L) → Si NO: Continuar Regla 6: ¿No es archivo y no es directorio? → Si YES: Reescribir a index.php ❌

? DESCONOCIDO: ¿Cuál regla se aplica?

4. Resultado final
ESPERADO: Se carga validar-extintor.html (página pública) ACTUAL: Se redirige a login ? PROBLEMA: El .htaccess está reescribiendo a index.php cuando NO debería

❌ Posibles Causas del Problema

  1. mod_rewrite no está habilitado en el servidor
    Apache no procesa las reglas RewriteRule
  2. REQUEST_FILENAME no detecta el archivo
    -f check falla aunque el archivo existe
  3. .htaccess en directorio padre está interfiriendo
    Tiene RegRewriteEngine Off u otras reglas
  4. DocumentRoot mal configurado
    REQUEST_FILENAME != ruta real del archivo
  5. Alias o RedirectMatch en virtualhost
    Redirect 302 /extintores /public/login.html
  6. Session/autenticación forzada
    PHP está redirigiendo incluso si es archivo estático

✅ Diagnóstico Necesario

Para resolver esto, necesito que verifiques en tu servidor:

  1. Abre: https://gestion.avba.com.mx/extintores/public/validar-extintor.html

    ¿Se carga la página de validación o redirige a login?

  2. Abre: https://gestion.avba.com.mx/extintores/public/validar-extintor.html?qr=43526180127

    ¿Se carga con el parámetro QR?

  3. Comprueba logs: Ver logs de Apache
    tail -f /var/log/apache2/error.log
  4. Verifica .htaccess: ¿Está en el servidor? intenta descargar .htaccess

🚨 Solución Más Robusta (Plan B)

Si el .htaccess no funciona, puedo implementar una alternativa:

  1. Crear endpoint PHP público en la raíz que NO redirige a login
  2. Cambiar QR para apuntar a ese endpoint en lugar de validar-extintor.html
  3. El endpoint PHP carga validar-extintor.html dinámicamente
